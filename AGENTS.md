# AI Agent Instructions for Fador's DOS Emulator

Welcome. You are assisting in building Fador's DOS Emulator.

## Core Directives
1. **Language & Standard:** Write modern C++20. Use `<concepts>`, `<ranges>`, `std::span`, `std::unique_ptr`, `constexpr`, etc. Avoid raw C-style arrays where `std::array` or `std::vector` fits better.
2. **Architecture:** The emulator is strictly decoupled. The CPU, Memory, and Hardware Devices must NOT depend on any UI backend. UI (Console/Text mode vs Graphical) must be implementations of a standard interchangeable interface.
3. **Reference Material:** The `docs/` folder contains comprehensive documentation (Ralph Brown's interrupt list).
   - `INTERRUP.*`: Interrupt definitions
   - `PORTS.*`: I/O port definitions
   - `OPCODES.LST`: Intel opcodes
   *Always consult these files when implementing an interrupt or port handler.*
4. **Development Strategy:**
   - Prioritize 16-bit real mode, 32-bit Protected Mode transitions, and core 386 instructions.
   - x87 FPU: `src/cpu/x87/` holds the model. `Float80` is the 80-bit value (`mant` with explicit integer bit, `signExp`); `x87::FPU` (owned by `CPU`, `cpu.fpu()`) holds the architectural state and the instruction semantics (stack faults, masked/unmasked exception responses, condition codes, computed tag word, FSTENV/FSAVE images in all four layouts); `InstructionDecoderFPU.cpp` decodes D8-DF/FWAIT, does the memory accesses and delivers pending unmasked exceptions at waiting instructions (#MF if CR0.NE, else the `CPU::setFPUErrorCallback` FERR# callback that `main.cpp` wires to IRQ13). Values are computed by a back end (`X87Math.hpp`): `host::` runs the operation on the host x87 (GCC/Clang x86/x86-64, hot paths inline in `HostX87Inline.hpp`), `soft::` is portable software 80-bit arithmetic (MSVC, ARM64, or `-DFADOR_SOFT_X87=ON`). Both must stay bit-exact with the host: run `fpu_fuzz` (and `fpu_fuzz --backend`) in both a normal and a `FADOR_SOFT_X87=ON` build after touching any of this; soft transcendentals are only required to be within 16 ulps. The emulator must not use `long double` arithmetic elsewhere (the host back end keeps the guest's control word loaded in the host x87).
   - DPMI host support exists for protected-mode DOS extenders: DOS/4GW, PMODE/W, DOS/32A, CauseWay and DJGPP programs run (`tests/compat`). Workarounds specific to DOS/4GW must stay gated on `InstructionDecoder::dos4gwReflectionStack()` so other extenders are unaffected.
   - CPU models (`src/cpu/CpuModel.*`, `--cpu=`): instructions that do not exist on every model must call `requireFeature(feature::...)` (raises #UD); give a new opcode a cost class in `cycleClassOf()`. Guest EFLAGS loads go through `flagsWriteMask()`/`writeFlags()` (Protection.cpp), never a raw `setEFLAGS()` of a popped value. `CPU::cycles()` is the model-weighted guest clock; `CPU::getCycles()` is the main loop's instruction/idle tick count.
   - Bootstrapping: Start by successfully loading and running simple DOS `.COM` files.
   - Memory Model: 128 MB of physical RAM (`MemoryBus`): XMS/DPMI pool 1 MB..`XMS_LIMIT`, VBE linear frame buffer at `VBE_LFB_BASE`, host tables from `SYSTEM_RESERVED_BASE`. CPU accesses use the linear `lread*/lwrite*` functions (paging-aware); HLE code, renderers and DMA use the physical `read*/write*` functions.
   - Testing: Write unit tests for your CPU instruction implementations.
5. **Memory Initialisation:** Conventional memory above the BDA (0x500–0x9FFFF) is filled with a deterministic pseudo-random pattern (LCG: `val = val * 141 + 3`, seed 0xCC) in `MemoryBus::MemoryBus()` to simulate dirty DOS RAM. IVT/BDA (0x000–0x4FF) remains zero-filled so BIOS `initialize()` can write proper values on top. The EXE/COM loader then writes image data over the fill. **Do not change this initialisation to all-zeros or all-0xCC** — programs compiled with Borland's mixed-model Turbo Vision (e.g. TC 2.01) read uninitialised far-heap memory: all-zeros causes false end-of-table sentinel matches; all-0xCC causes buffer overflows from unterminated strings. The LCG pattern provides ~255 non-zero bytes between natural zeros, avoiding both failure modes.
6. **Build System:** Maintain the `CMakeLists.txt`. Ensure it compiles consistently natively on all target platforms (Windows, Linux, macOS) without relying on OS-specific extensions where C++ standard library equivalents exist.
7. **Built-in Disassembler:** A read-only x86 real-mode disassembler lives in `src/cpu/Disassembler.{hpp,cpp}`. It reads bytes from `MemoryBus` and produces `DisassembledInstruction` structs (address, length, mnemonic, hex bytes) without modifying any state. Use `disassembleAt()`, `disassembleRange()`, or `disassembleAround()` to inspect code. When adding new opcodes to `InstructionDecoder`, mirror the decoding in the disassembler's `disasmOpcode()` / `disasmOpcode0F()` methods.
8. **Debugger & Cycle Stop:** The interactive debugger (`src/ui/Debugger.{hpp,cpp}`) provides single-step, register dump, memory dump, disassembly, and inline assembly commands. The `--stop-after=N` CLI flag halts execution after N instruction cycles and calls `Debugger::dumpState()` to print registers and surrounding disassembly. `--stop-after-debugger` enters the debugger at the stop point. `--dump-on-exit` dumps state when a program terminates. `--exec="asm"` assembles and executes instructions without loading a program. `--bench=name` runs in-process benchmarks (decoder-loop, rep-movsb, rep-movsd, rep-stosd; render-13h, render-modex, render-planar, render-vbe, audio-mix, mem-fill for the host-SIMD kernels) without guest startup noise.
9. **Built-in Assembler:** A real-mode x86 assembler lives in `src/cpu/Assembler.{hpp,cpp}`. It converts assembly text into machine-code bytes via `assembleLine()` (single instruction) or `assembleBlock()` (multi-line). The assembler supports the same instruction subset as `InstructionDecoder`: ALU, MOV, shifts, jumps (short/near), Jcc, CALL/RET, PUSH/POP, INC/DEC, NOT/NEG, MUL/DIV, IN/OUT, string ops, segment overrides, MOVZX/MOVSX, BT family, LEA, LES/LDS, ENTER/LEAVE, INT, XCHG, TEST, and more. When adding new opcodes to `InstructionDecoder`, add corresponding encoding support in the assembler.
10. **Temporary Debug Code Policy:** Do not leave `fprintf(stderr, ...)` tracing, hardcoded address watchpoints, synthetic key injection, or per-program diagnostic blocks in production code. Use the `LOG_*` macros for permanent logging. If you add temporary instrumentation during a debugging session, remove it before committing.
11. **Testing Strategy:** Besides the unit tests, run `cpu_fuzz` after touching integer instructions, `fpu_fuzz` after touching the x87 (normal and `FADOR_SOFT_X87=ON` builds), `tests/perf/run_profiles.py` after touching hot paths (compare against `tests/perf/README.md`), and `tests/compat/run.sh` after touching DPMI, DOS or interrupt code. The DOS test programs run unattended with `--headless --max-seconds=S --keys=... --screenshot=...`.
    Unit tests use a custom lightweight framework (`tests/test_framework.hpp`). Tests are organized by subsystem: CPU behavior, instruction decoding, addressing modes, interrupts, BIOS HLE, DOS services, memory management, directories, drive/search, hardware devices, assembler, and assembler-driven interrupt integration tests. When adding new interrupt handlers or instructions, add corresponding tests. The assembler-driven tests in `test_int_asm.cpp` exercise the full pipeline (assemble → write to memory → decode/execute → HLE handler) and should be extended for new handlers.
12. **Audio Subsystem:** AdLib (OPL2 / YM3812) at ports 0x388–0x389 and Sound Blaster DSP at ports 0x220–0x22F are both emulated; `--gus` adds a Gravis Ultrasound (`src/hw/audio/GravisUltrasound.*`). The audio is mixed into a single PCM stream and forwarded to the platform's native audio backend (SDL2 Audio on Windows). Sound Blaster DMA uses the 8237 DMA controller for transfers; both single-cycle and auto-init DMA modes are supported (8-bit and 16-bit, mono and stereo). The SB IRQ (typically IRQ 5) fires on both DMA Terminal Count and DSP block-completion, which is critical for auto-init DMA games (e.g. DOOM, Wings) that program a DMA buffer larger than the DSP block size. When debugging audio issues, check that the SB's `m_dmaLength` block counter decrements correctly in `generateSamples()` and that the DMA controller's `acknowledgeTransfer()` returns TC when the channel count wraps. The GUS follows the emulated-time device pattern: every port access first runs the GF1 to the current time (`sync()`), `advanceTo()` only when its predicted next interrupt (voice wavetable/ramp IRQ, timer, DMA TC) is due, and `generateSamples()` resamples the GF1-rate stream onto the main loop's 44.1 kHz frame grid. If a register write can make an interrupt happen sooner, it must call `invalidateEvents()`; the event prediction (`ticksToVoiceEvent`) must stay a lower bound of what `renderVoice` does. DMA devices check `DMA8237::isMasked()` before transferring and can use `DMA8237::addMaskListener()` to start when a program unmasks their channel (no polling).
13. **Crash Handling:** A crash handler is installed at startup that catches signals/SEH exceptions and prints a dump containing CPU registers, disassembly around EIP, a stack trace, and text-mode VRAM contents. The crash dump callback uses raw `fprintf` to stderr to stay safe inside signal handlers.
14. **Host SIMD dispatch:** Host-side bulk work (frame conversion, audio mixing/conversion, REP STOS fills) goes through `fador::utils::simd::kernels()` (`src/utils/simd/Simd.hpp`), never through raw intrinsics elsewhere. To add a kernel: (1) add a function pointer with a precise per-element definition to `Kernels`; (2) write the scalar reference in `KernelsScalar.cpp` (declared in `KernelsInternal.hpp`) and register it in `installScalar()`; (3) add ISA variants only where `--bench` shows a real gain, in `KernelsSSE2.cpp` / `KernelsSSE41.cpp` / `KernelsAVX2.cpp` (every function marked `FADOR_TARGET("...")`, never global `-m` flags) or `KernelsNEON.cpp`, handling the tail by calling the scalar kernel, and register them in that file's `install*()`; (4) extend `tests/test_host_simd.cpp` so every level is compared bit for bit with the scalar kernel on random data, odd sizes and unaligned pointers (no FMA contraction or other reassociation in float kernels). Run the tests with `FADOR_HOST_SIMD=scalar` and with the default level. Host CPU features come from `utils::hostCpuFeatures()` (`src/utils/HostCpu.hpp`).
15. **Logging & Tracing:** The `--trace=<cats>` and `--debug=<cats>` flags enable category-filtered logging (cpu, video, dos). `--instruction-trace=N` prints a one-line trace per instruction. `--instruction-trace-step` pauses between traces for interactive stepping.

16. **Emulated Time:** Devices never read the host clock. `hw::VirtualClock` (`src/hw/VirtualClock.hpp`) is the single time base: it advances with retired guest work, normally the CPU model's guest clock `CPU::cycles()` at the CPU clock rate (`--throttle-ips` counts instructions instead), plus explicit `advanceCycles()`/`waitUntil()`, and main.cpp paces it against the host (auto / `--throttle-*` / `--deterministic`). `hw::MachineTime` (`src/hw/MachineTime.*`) ties the CPU to it: `planSpeed()` resolves `--cpu`/`--throttle-machine`/`--throttle-ips`/`--deterministic` into a model and clock, `configure()` attaches the counter and installs the CPU's TSC source (emulated ns x core clock) and HLT callback, `halt()`/`guestIdle()` wait for the next device event. A device that raises interrupts on its own must be registered with `machineTime.addWakeSource(nextEventNs)` so HLT and idle waits wake for it. A timed device takes `setTimeSource(std::function<uint64_t()> nowNs)` (wired with `clock.timeSource()`) and evaluates elapsed time lazily on port access; the main loop calls `advanceTo(now)` between batches, which must stay a single compare until the device's next interrupt is due. Blocking HLE waits call the BIOS/DOS idle callback instead of sleeping. Guest-visible date/time comes from the RTC (`CMOSRTC::dateTime()`), the BIOS tick count and the DOS date (`DOS::readClock()`), never from `std::time`/`system_clock` (host file timestamps excepted). Keep `--deterministic` runs reproducible: no wall-clock reads in anything that affects guest state; check with `tests/timing/check_time.py` after touching any of this.
17. **VGA:** `VGAController` is the register file; plane memory uses the IBM layout (chain-4 puts CPU address A in plane A&3 at offset A&~3; text characters/attributes stay in RAM at B8000h/B0000h, fonts in plane 2). `FrameRenderer` derives everything from the registers (`decodeLayout`), so the BIOS must program real register values: INT 10h mode sets load the IBM VGA parameter tables in `BIOSVga.cpp`. HLE code that moves the text cursor by writing the BDA must call `hw::syncCursorFromBDA()`. Retrace (port 3DAh) uses the time source passed to `VGAController::setTimeSource()`.
18. **Interpreter fast paths:** `InstructionDecoder::step()` first tries the predecoded fast path (`tryFastPath`, `src/cpu/FastPath.cpp`), then the legacy decoder (`executeOpcode` / `executeOpcode0F`). `run(n)` (used by the main loop) executes consecutive fast-path instructions in bursts (`runFastBurst`) with paging off. Invariants contributors must keep:
   - **Flags are lazy.** ALU ops record `(kind, size, operands, result)` with `CPU::setLazyFlags()` (`src/cpu/LazyFlags.hpp`); `getEFLAGS()` folds them in, `setEFLAGS()` drops them, so every reader (HLE services, PUSHF, exceptions, debugger) sees architectural values. Write *some* arithmetic flags with `CPU::setArithFlags(mask, value)` (shifts, MUL, CLC/STC), read CF/ZF/conditions with `carryFlag()` / `zeroFlag()` / `testCondition()`, and DF/IF etc. without materializing via `directionFlag()` / `getEFLAGSNonArith()`. Never touch `m_eflags` arithmetic bits directly. #PF restart saves/restores `saveFlagsState()`.
   - **Adding an opcode:** implement it in the legacy decoder first (and the disassembler/assembler, cycle class). Put it on the fast path only if it is hot: add a handler to `FastOps` and a case in `decodeFast()`. The handler must have exactly the legacy code's effect: same registers, flags, memory accesses in the same order (VGA window, #PF restart), and `DecodedInsn::cycles` must equal what the legacy path charges (cycle-table entry + memory-operand cost when the legacy code calls `getEffectiveAddress*` + extras such as the MUL surcharge). Handlers must not change CS, start an interrupt shadow, enable paging, end the program or raise exceptions; anything that might stays legacy (return a null handler) or, like x87 (`kX87`), is gated so the risky case runs on the legacy path. Segment loads other than CS/SS are allowed (they go through `loadSegment()`).
   - **No invalidation needed:** decoded entries are verified byte-for-byte against memory (through `MemoryBus::codeWindow()`, translated like a fetch) before every execution, so self-modifying code, DMA/file loads over code and page remapping are safe; instructions crossing a page's last 15 bytes, wrapping IP in 16-bit code, or outside plain RAM always use the legacy decoder. The cache is flushed only on a CPU model change.
   - **Testing:** `tests/test_interpreter_fast_paths.cpp` runs random 16/32-bit (and paged) instruction streams through the fast and legacy paths in lockstep and compares registers, flags, x87 state, memory and both cycle counters (`FASTPATH_FUZZ_SEQUENCES=N` for long runs); `cpu_fuzz` (now also 2-5 instruction sequences) compares with the host. For whole programs compare `--deterministic` runs with and without `--no-fast-path`: instruction count, the exit log's guest cycle count, emulated time and output must match.
   - Bulk REP MOVS/STOS into the VGA window go through `MemoryBus::lwriteVgaElements()`, which must stay byte-for-byte equivalent to `write8Slow()`.
19. **Serial / parallel ports:** `Uart16550` and `ParallelPort` are the register files; what is plugged in implements `SerialBackend` (`src/hw/SerialBackend.hpp`: transmit/controlLines on emulated time, hasData/take for received bytes, `poll()` for host I/O) or `ParallelDevice` (`src/hw/ParallelPort.hpp`). Host I/O (sockets, files, host mouse) happens only in `poll()`, called from main.cpp's periodic services, never from a port access. Sockets go through `utils::TcpStream`/`TcpListener` (`src/utils/HostSocket.*`), the only place with Winsock/BSD socket code. `INT 14h`/`17h` reach the ports through the I/O bus at the BDA addresses (`BIOSPorts.cpp`).
